Oracle 剛剛做了一件幾乎不可能的事：它同時告訴全世界「AI 寫的程式碼是我們未來的核心競爭力」和「AI 寫的程式碼不准出現在我們管理的開源專案裡」。這兩句話之間沒有矛盾——如果你看懂了 Oracle 的商業模型的話。The Register 的 Lindsay Clark 把政策公告、21,000 人裁員、$700 億資料中心投資、和信用評級降級四個點串成同一條線，這篇文章本身就是科技新聞應該長成的樣子。

## 原文摘要

Oracle 近日通知 OpenJDK 貢獻者：不要提交由 AI 生成的程式碼或其他內容。這篇標記為「legal」的公告表示，Oracle 正在起草一份正式的生成式 AI 政策，但先公布了臨時基本規則。公告列舉的風險包括：審查負擔、安全性、以及智慧財產權問題。

「OpenJDK 社群的貢獻不得包含由大型語言模型、擴散模型、或類似的深度學習系統部分或全部生成的內容，」公告寫道。「內容」的定義涵蓋 OpenJDK Git 倉庫中的原始碼、文字與圖片、GitHub pull request、郵件訊息、wiki 頁面、以及 Java Bug System 議題。

Oracle 補充說明，開發者仍然可以在私下使用 LLM 工具來「幫助理解、除錯、審查 OpenJDK 程式碼和其他內容，以及進行與 OpenJDK 專案相關的研究」——前提是不得將這些工具生成的內容提交為貢獻。

公告進一步闡述了 AI 生成貢獻對審查者的潛在負擔，以及相關的安全與智財疑慮。Oracle 指出，OpenJDK 是眾多組織的主要 Java 實作版本，支撐著全球的關鍵業務系統。「安全是最高原則。看起來合理但實際錯誤的程式碼會將這些關鍵特性置於風險之中。」

這份謹慎的態度，和 Oracle 在自己公司內部對 AI 生成程式碼的熱情形成了鮮明對比。

「Oracle 正在寫的程式碼，不是 Oracle 在寫的，」共同創辦人暨技術長 Larry Ellison 在 Oracle AI World 2025 上說。「我們的 AI 模型在寫。我們只是告訴模型我們想要程式做什麼，然後 AI 就會產出一個逐步執行的流程。我們不寫程序，我們宣告意圖，但模型寫出那個我們通常稱之為電腦程式的東西。」

今年稍早，共同 CEO Mike Sicilia 表示：「如果我們不採用 AI 工具，它們的程式碼能力會是威脅——但我們正在採用，而且非常快速。Oracle 內部使用 AI 程式碼工具，讓更小的工程團隊能更快地為客戶交付更完整的解決方案。」

AI 也出現在 Oracle 六月裁員 21,000 人的說明中。「AI 技術在我們各項營運中的部署，已經造成、且可能持續造成我們人力縮減，」Oracle 在聲明中表示。

Oracle 同時宣稱，嵌入其應用程式中的 AI 代理能夠推理、做出商業決策、並代表使用者採取行動。

為什麼 AI 生成的程式碼適合 Oracle 的產品，卻不適合 OpenJDK 的貢獻？The Register 對此表示困惑。

在這個時候公開質疑 AI 可靠地代表人類行事的能力，對 Oracle 來說可能相當尷尬。這家資料庫巨頭上個月宣布，將在未來一年投資 $700 億美元用於資料中心建設，高於 2026 財年的 $557 億。信評機構 S&P 隨即將其信用評級下調至 BBB-——僅比垃圾級高一級，並表示從這些投資中獲利的途徑不明確。

Oracle 正在大量舉債來支應建設計畫，同時承受負現金流。最近，Oracle 的信用違約交換利差急劇上升，顯示為違約風險投保的成本變得更高了。

## 城武觀點

先把結論說清楚：Oracle 不是偽君子，Oracle 是房東。這兩個身分的行為邏輯完全不同。

**OpenJDK 是 Oracle 管理的公地，Oracle 的產品是圍牆花園。** 在公地上，人類寫的程式碼是免費投入；在圍牆花園裡，AI 寫的程式碼是營收引擎。Oracle 不直接從 OpenJDK 賺錢，它的營收來自 Java SE 訂閱和 Oracle Cloud。禁令不是關於安全——是關於誰承擔風險。如果 AI 程式碼在 OpenJDK 裡是安全風險，在 Oracle Cloud 裡就不是，那「安全」只是商業邊界的別名。

這是「責任外部化」的經典案例：Oracle 把 AI 程式碼的利益（省人力、加速開發、提高營收）留在內部，把風險（審查負擔、安全漏洞、智財爭議）外部化給開源社群。公地的規則和圍牆花園的規則不是同一套——因為它們服務的是同一個主體的不同帳本。

**但真正的問題更深一層：Oracle 不信任自己押上整個農場的賭注。** 把四個資料點並排——OpenJDK AI 禁令、裁員 21,000 人歸因 AI、$700 億資料中心投資、S&P 降級至 BBB-——這不是四條新聞，是同一張圖。Oracle 需要 AI 成功（為了產品、為了敘事、為了股價），但 OpenJDK 是這個賭注的負債。AI 在 Oracle 內部產品犯錯是 B2B 合約可以吸收的風險；AI 在 OpenJDK 犯錯是全世界工程師用 git blame 追溯的公開紀錄。禁令不是安全措施，是責任歸屬的可追溯性：AI 寫的程式碼沒有作者，Oracle 的治理模型需要一個可以被 blame 的人類。

$700 億和 BBB- 的組合暴露了賭注的脆弱性：一家公司借錢賭 AI 的未來，同一時間對自己最重要的開源基礎設施說 AI 不准進來。這不是偽善，是誠實——Oracle 比任何人更清楚它賣的 AI 故事和它信的 AI 現實之間的差距有多大。

當一家公司向投資人說「AI 以經在取代我們的工程師」，同時向開源社群說「AI 寫的程式碼不准提交」，它不是在說謊。它是在對兩個不同的對象說兩件不同的事實。兩件事都可能是真的。但只有其中一件事會出現在財報電話會議上。

*城武的未解檔案——Oracle 對 AI 的信心，大到可以拿來賣錢，但沒有大到可以拿來維護全世界都在用的免費程式碼。這兩件事之間的量尺，就是這家公司真正的 AI 信仰深度。*
