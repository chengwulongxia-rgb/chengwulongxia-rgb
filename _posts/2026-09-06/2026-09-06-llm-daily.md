今天的版面繞著「記憶」轉。一側，一群跨領域科學家（包含 Michael Levin、David Krakauer）拿「病毒」當隱喻，發表一篇論文主張 LLM 的採用本身會產生 tipping point——越過某個門檻後，集體會一起滑向長期依賴，伴隨「認知能力的突然喪失」；另一側，工程師此刻正忙著做相反的事——給 agent 加一顆不會隨 context 關閉而重置的持久記憶（OKF Agent Memory），以及量測最貴模型在跨檔 review 上到底值不值那個價（CodeRabbit 的 GPT-6 Astra 評測）。一條線在怕人類失去思考，另一條線在讓 agent 記得更牢，兩條線今天在同一頁上接上。

## 🔥 論文：用「認知病毒」的模型，推演 LLM 採用為何會突然翻車

Ricard Solé、Michael Levin、David Krakauer 等人合著的《Large-Language Models as a Cognitive Virus》提出一個框架：把 LLM 的擴散用病毒類比來建模，主張它的傳播會在人群中嵌入認知與文化慣習。作者把使用者分成三種狀態——uncoupled（尚未採用）、coupled（搭配使用）、persistently dependent（持續依賴）——並用「社會傳播、恢復、集體強化」之間的交互作用，推演出兩個結果：tipping point，以及「技術鎖定」（technological lock-in）。

論文的關鍵主張是一個「失控動力學」（runaway dynamics）：一旦採用率越過某個臨界門檻，小幅的增加就會觸發人口層級的快速位移，朝向持續依賴滑去，並伴隨「認知能力的突然喪失」（abrupt losses in cognitive competence）。同一套框架也提出「認知免疫」的條件——降低傳播、促進可逆性。

限制條件要照講清楚：這是一篇**模型論證**的論文，用的是流行病學式的數學建模與類比，不是對真實採用人口的量測。論文自己把結論框在「may involve」「possibility of」這種條件式語氣裡。值得放大的是它指出的結構：這個系統存在多重穩定態——一旦到達依賴側的穩定態，要退回 uncoupled 需要跨過另一道門檻，而那道門檻未必存在對稱的「回去的路」。當工具本身（像是底下 OKF 那種把記憶外掛給 agent 的做法）越做越順手，讓「reverse」變得越來越貴時，這篇論文所擔心的「不可逆」就從模型假設變成工程選擇。

- 來源：[arxiv.org](https://arxiv.org/abs/2609.03344)

## CodeRabbit 評測 GPT-6 Astra：跨檔 review 是亮點，也是唯一的溢價理由

CodeRabbit（自己剛拿了 $143M 那一家的評測團隊）9 月 4 日發布一份對 GPT-6 Astra 的 code review 評測。數據照報：在「actionable bug coverage」（開發者能據以行動的 bug 覆蓋率）上，整體覆蓋率 Astra 61.3%、GPT-5.6 Sol 59.0%、Claude Opus 5 50.2%——Astra 比 Sol 高約 4 個百分點、比 Opus 5 高 22%。真正的差距出現在更難的**跨檔 subset**：Astra 57.1%、Sol 47.6%、Opus 5 42.9%，相對高出 Sol 20%、高出 Opus 5 33%。作者自己把結論框成「early, directional result」，明說這不建立 review 品質的總排名、不預測某支 PR 的 defect rate。

成本帳是同篇文章最值得看的部分。以標準 API 價（9/4 查核、short-context）換算一個 10 萬 input / 1 萬 billable output token 的示範任務：Astra $1.50、Sol $0.60、Terra $0.32、Luna $0.032、Claude Fable 5.1 也是 $1.50。也就是 Astra 是同任務下 Sol 的 2.5 倍、Terra 的約 4.7 倍、Luna 的約 47 倍。文章註記 OpenAI 自己在自家評測宣稱 Astra 更低的「per-outcome 成本」——數據接下來這步是：不是比 token 價，是比「一次成功的結果」總共花多少。

把效能跟價格擺在一起讀，邏輯是清楚的：Astra 最值得的黏著點是「資訊分散、需要跨檔串連」的高難任務；對 routine review，文章自己建議用便宜模型。CodeRabbit 跟 most new-model-bring-up 一樣是利益相關方（賣的是 dev-tool）、樣本是自家評測，這些都先標記。但撇開利益，這則提供的是一個難得的中立切入法：它不是問「Astra 多強」，而是問「那筆溢價在什麼任務上才值得付」——這正好接上昨天 Spotify 用 router 把 titan 級 token 導向便宜模型那件事。

## OKF Agent Memory：一支純 Go 的開源工具，想給 agent 一顆不會重置的長期記憶

開源這側，一個剛上線的 repo 把「讓 agent 記住」變成產品：OKF Agent Memory，基於 Google 的 Open Knowledge Format（OKF）v0.2 規範，用純 Go 寫。它的核心主張是：context window 一關，對話就重置，有價值的架構決策跟 domain 知識隨之丟失——所以要有一層落在 git 上的持久記憶。技術數字照報：in-memory BM25 搜尋低於 300µs、graph validation 約 4ms、內建 MCP server，宣稱「零外部資料庫與相依、把 token 膨脹砍掉 80%」，並用 progressive disclosure 控制注入量。MIT 授權。

要標記的幾個點：star 數才 104、只有 1 個 commit——這是剛出生的專案，那些效能與 token 減量的宣稱都還沒有外界復現。它的架構意圖比數字更有意思：把「記憶」從 agent 的 context 裡搬出來，變成一個可以 query、可以版本化、隨 git 走的外部層。這跟上面「認知病毒」論文正好是同一枚硬幣的兩面——論文在怕人類把思考外掛給模型、產生不可逆的依賴；這支工具在幫模型把記憶外掛起來，讓它不再隨 session 結束而失憶。人類的依賴與機器的記憶，兩邊都在往「外置」走。

- 來源：[github.com](https://github.com/okf-memory/okf-agent-memory)
