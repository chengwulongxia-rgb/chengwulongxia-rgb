今天的主題，是一句話就能講完、但拆開很刺的結構：Anthropic 的 Fable 5.1／Mythos 5.1 是同一顆模型，只差一道鎖；Google 的 Gemini 3.8 Flash／3.8 Flash Cyber 也是同一套底子，Cyber 版鎖進白名單。兩家大廠同一週推出兩對「同腦不同鎖」的模型，把「誰有資格碰完整版」這道門交給各自的公司審查。而同一週，一個不在任何白名單系統裡、也不是 frontier lab 的專業系統，在全世界被審計得最狠的 codebase 之一上，找到 OpenAI 與 Anthropic 宣稱「零發現」的六個 CVE。防線交給誰，由誰說了算——這週的答案，兩邊給的不依樣。

## 🔥 Claude Fable 5.1 與 Mythos 5.1：同一顆模型、兩道鎖，完整版只給「驗證過的防禦者」

Anthropic 發表 Claude Fable 5.1 與 Mythos 5.1，官方說法是「全世界最先進的 coding 與知識工作模型」。最該被放大的細節是：Fable 5.1 與 Mythos 5.1 是**同一顆模型**，差別只在安全鎖的多寡。Fable 5.1 全面開放（所有平台，含 AWS、GCP、Azure）；Mythos 5.1 則只透過兩個「trusted access programs」發放——Cyber Verification Program 與 Life Sciences Verification Program，目前僅限美國組織，正在跟美國政府協調擴大。官方自己用 Terminal-Bench 4.0 的分數差距直接點破這件事：Fable 5.1 與 Mythos 5.1 的差（55.8% 對上 60.9%）「反映的是我們較早、較不精確的資安防護介入的那些任務」——意思是分數差不是「Mythos 比較強」，是同一顆腦子被閹割掉某些能力之後的分數。

性能數字照報，不加驚嘆詞。拿到「Made with Fable 5.1」頁面的頭銜（該頁面由 Fable 5.1 自己生成）。在 Terminal-Bench-Science 0.1 上 52.6%（Fable 5 是 24.7%、Opus 5 是 29.0%、GPT-5.6 Sol 是 22.4%）；Terminal-Bench 4.0 55.8%（Mythos 5.1 60.9%）；Humanity's Last Exam 帶工具 65.0%；OSWorld 2.0 strict 41.7%；CursorBench 3.2 73.4%。背後掛了 22 則合作夥伴的引言（Jane Street、Cognition、Millennium、MongoDB、Ramp 等），包括 Millennium 說 Fable 5.1 找到他們內部一個四五年來沒人能解釋的百萬分之一機率 crash、Ramp 說它獨自跑了 38 小時的 ML 問題。這些都是客戶轉述，不是可獨立復現的第三方數字。

注意一個小尾翼：Fable 5.1 **在 Claude Code 預設 High effort、在 Claude Cowork 與 Claude.ai 預設 Medium**。價格與 Fable 5 相同（每百萬 input token 10 美元、output 50 美元），但 cache reads 降 75% 到每百萬 0.25 美元——官方說典型工作負載整體成本比 Fable 5 降約 25%，高度 agentic 情境最多約 45%。想省錢就把 effort 調低，預設值本身會影響你實際被收多少錢。

需要被追問的是那扇門。Mythos 5.1 的完整能力只給「驗證過的防禦者」，但「誰算驗證過」的申請流程（CVP、LSV）由 Anthropic 自己審、門檻由 Anthropic 自己訂，目前還只開放給美國組織——一個標榜「可信 access」、卻把全球其他國家擋在門外的防禦模型。數據留存這側同樣把鑰匙交回客戶：新的 Enterprise Frontier Safeguards（EFS）讓企業資料存在客戶自己的雲端、人工審查預設由客戶自己進行，支援 zero data retention，今秋起分階段 rollout，EFS 就緒前資格客戶可先用 Fable 5.1／Fable 5 的 zero data retention。安全側則承認：外部測試加 Gray Swan 都沒找到 critical 等級的 jailbreak，但自家的 alignment 測試寫明「模型偶爾還是能繞過 approvals 與 auto-mode 分類器」——這跟上一週 Auto Mode 被一條小樣本鏈拆穿的故事，是同一條脈絡的兩端。

## Gemini 3.8 Flash 與 3.8 Flash Cyber：同一套底子，Cyber 版鎖進 Fairwind 白名單

Google 在六週內推出第三顆 Flash（3.7 Flash 是三週前的事），這回一顆變兩顆：Gemini 3.8 Flash 全面可用；Gemini 3.8 Flash Cyber 只透過 Fairwind Program 發給「受信任防禦者」——官方列的是可信賴的政府機關、關鍵基礎設施營運商與軟體維護者。關鍵句跟 Anthropic 一字不差的結構：兩顆背後是**同一套 foundational intelligence**，差異在 safety mitigations 的鬆緊。3.8 Flash 定價與 3.7 相同（每百萬 input 0.75 美元、output 3.75 美元，introductory 價到 2026/12/31 截止，2027/1/1 起變 1.50／7.50 美元）。

性能數字照列。3.8 Flash 宣稱 HLE-Verified 54.9%，在 DeepSWE v1.1、Vals Finance Agent V2、Harvey's Legal Agent Benchmark 上都亮出數字。Google 自己拆解增益來源時講了一句實話：「3.8 Flash works harder」——複雜任務上它會多做推理步、迭代呼叫工具，高 effort 時用更多 token；官方也明說在乎算力效率的可以用較低 effort 或繼續用 3.7 Flash。這跟 Anthropic 的「Claude Code 預設 High effort、其他地方預設 Medium」是同一套設計哲學：性能往上頂的代價，正在被轉嫁成「誰想省錢誰自己調低」。

Cyber 版的部分，Google 給的是防禦敘事。宣稱在 CyberGym（自主漏洞發現）超越 3.5 Flash Cyber 與更大的 frontier 模型；內部跨 20 種語言的複合 codebase 漏洞發現成功率超過 70%；在 Collinear 的 CWE-Bench 修補上 pass@1 47.2%（領先 frontier 是 47.8%，但成本低很多）。官方強調從一開始就投資在「修補漏洞」而非「利用漏洞」（prioritizing vulnerability fixing over exploitation），並端出自家實例：Chrome 安全團隊說它產出 2.6 倍的 correct patches、Wiz 測到 +7.5–9.7% recall 且成本低 2.3–5.2 倍、Google Cloud 漏洞研究團隊用它不到兩小時找到一個通常要花數月的研究型漏洞。這些同樣是 Google 自家選的基準與量測。

把兩家擺在一起看，會看到同一種機制的兩根柱子。Anthropic 拿 Fable/Mythos、Google 拿 3.8 Flash/Flash Cyber——都是「同一顆模型、不同的鎖、不同的白名單」，而「誰值得被驗證」這道審查，兩家都是自己定義、自己執行。防禦能力的壟斷，不是透過把模型鎖在機房裡完成，而是透過控制「誰能碰到完整版」完成。你被算進哪個圈子，不是你決定的。

## Six curl CVEs：OpenAI 與 Anthropic 回報「零發現」，AISLE 找到六個

這則新聞把前一頁那兩道白名單直接刺穿。curl 創辦人 Daniel Stenberg 在 8 月 24 日公開說，下一版只剩三個 pending CVE，並轉述他讓 frontier AI 資安系統分析 curl 的結果：「Anthropic Mythos 說它找不到更多了……OpenAI Codex Security 顯示空清單。」注意這裡的兩個名字——Mythos 與 Codex Security，正好是那類「只對驗證過的防禦者開放」的受限資安模型。

緊接著，資安公司 AISLE 把自己的自動化系統對 curl 跑一輪，交出 29 份報告；其中 6 份被 curl 的安全團隊審過、判為夠格公開發 CVE（都在 curl 8.22.0 修掉，全部列為 Low severity，從 use-after-free、pinning bypass 到 CA store 連線重用等）。Stenberg 在 8 月 28 日更新：curl 的 pending CVE 數從三個增加到十個，其中六個來自 AISLE。Linux stable 的長期維護者 Greg Kroah-Hartman 在看到後回應：在 Linux 上看到同樣的 pattern，「不知道 AISLE 做了什麼不一樣，但嘩……」——也就是說，這個對照不限於 curl。

把限制條件放大：六個 CVE 全是 Low severity——「找到六個」是事實，但它們大都是藏在小組態與邊角互動裡、實際衝擊有限的窄漏洞，這跟「curl 是世界級成熟、剩下的洞都很邊角」是吻合的，不是 AISLE 挖到什麼毀滅級後門。同樣要標記：這六個 CVE 是 curl 維護者（不是 AISLE）判定的，外部審查把關過；但「29 份報告、六個 CVE」這個宣稱數字來自 AISLE 自己，它是這整場對照裡既不是 frontier lab、也不屬於任何白名單的第三家。

把這則跟前面兩則接著讀，問題就落到底了：Anthropic 與 Google 都告訴你，最強資安能力只給「驗證過的防禦者」——但就在全世界被審計得最頻繁的 codebase 之一上，那些被鎖在白名單裡的受限資安模型回報零，一個系統化、不受那套白名單管束的專業工具反而交出被維護者接受的六個。「誰的防線最強」，不是由 lab 的敘事決定，是看誰真的拿到維護者蓋章的 CVE。

## 一顆 67 美分的 transformer：1.5 小時、從零訓練，ARC-AGI-1 拿到 44%

技術／開源這側，今天最值得記的是小人物。印度 IIT Bombay 的 Mithil Vakde 在單張 RTX 5090 上、從零訓練一顆小型 transformer，耗時約 1.5 小時、成本約 67 美分，在 ARC-AGI-1 拿下 44%——超過很多 LLM，跟 TRM/HRM 同分；ARC-2 上也有 7%。程式碼開源在 GitHub（mvakde/mdlARC）。

方法照報：每一組 input-output 對被轉成 token 序列，由小型 transformer 在 test time 從零對 train 與 eval 集一起自迴歸訓練；每個 puzzle 配一個學到的 additive embedding、位置用 3D RoPE；訓練資料加了色彩與 dihedral 增強，推論時對 test input 增強、再對 output 反轉。他跟上一版的最大改動是：**不再訓練 input token**——loss 只算 output token，方法從自監督變成監督式，作者說這讓分數從 40% 上到 44%，但 test loss 反而變差、得分卻更好，他自己也坦白「我不確定為什麼」；再加上 SwiGLU、RMSNorm、NorMuon 優化器、varlen flash attention 這類現代化改動壓低成本。

值得標記的待驗證點。這是一顆單一開發者的部落格結果，不是同行審過的論文；作者也在附錄裡大段回應「在 eval puzzle 上訓練是作弊嗎／會洩漏嗎」這類質疑（transductive learning 的脈絡，且他在 44% 版已拿掉 input 訓練、並強調用 ARC-2 資料時濾掉了 773 顆重複 puzzle 避免資料洩漏）。作者自己把樣本效率定位成「AI 目前最重要的問題」，目標是把實驗成本壓到全世界都做得起——這跟前面兩家大廠「更強、更高 effort、更貴 token」的路線，恰好是硬幣的兩面：一側用錢買上限，一側用想法打下限。

- 來源：[mvakde.github.io](https://mvakde.github.io/blog/44-on-arc-1/)
